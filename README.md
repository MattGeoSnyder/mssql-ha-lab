# mssql-ha-lab

An automated pipeline for building a **Windows Server 2022** golden image on
KVM/QEMU — the foundation for a SQL Server **Always On availability group**
home lab. The image is built with [Packer](https://www.packer.io/); Terraform
(to provision the VMs) and Ansible (to configure Active Directory, the Windows
Failover Cluster, and the SQL Server availability group) are planned next.

---

## What this builds

`setup.sh` produces a single, reusable **golden qcow2 image**:

- **Windows Server 2022 Standard (Server Core)** — CLI-only, installed unattended.
- **VirtIO drivers baked in** (`vioscsi` storage, `NetKVM` network, `Balloon`
  memory) so the guest runs with paravirtualized hardware under KVM.
- **Generalized with `sysprep /generalize`**, so every VM cloned from it gets a
  unique machine identity — required for domain join and failover clustering.
- **A bootstrap answer file** at `C:\Windows\Panther\unattend.xml` that re-enables
  WinRM on first boot, so a freshly-cloned VM comes up reachable for Ansible.
- **A UEFI fallback bootloader**, so clones boot without depending on host NVRAM.

The image is intentionally thin: identity and role (domain controller vs. SQL
node) are assigned later by Terraform and Ansible, not baked in.

## Prerequisites

- **Arch Linux host** — the dependency step uses `pacman`.
- **Hardware virtualization** enabled (`egrep -c '(vmx|svm)' /proc/cpuinfo`
  should be non-zero).
- Enough resources for the build VM (2 vCPU / 4 GB RAM, transient) and disk
  space for the ISOs and output image (~10 GB working).

The dependency step installs: `qemu-base`, `qemu-img`, `libvirt`, `edk2-ovmf`,
`wimlib`, `tigervnc`, `dnsmasq`, `packer`, and `libisoburn` (for `xorriso`).

## Before you build: download the Windows ISO (manual step)

This is the one step that **cannot be automated** — Microsoft gates the ISO
behind a registration form.

1. Download the **Windows Server 2022** evaluation ISO (free 180-day trial) from
   the Microsoft Evaluation Center:
   <https://www.microsoft.com/en-us/evalcenter/download-windows-server-2022>
   (choose the **ISO** download, 64-bit).
2. Save it as **`SERVER_EVAL_x64FRE_en-us.iso`** in:
   ```
   packer/iso/windows/
   ```

The `virtio-win` driver ISO *is* downloaded automatically (pinned to a specific
version and checksum-verified).

## Usage

Run the whole pipeline:

```bash
./scripts/setup.sh
```

Or run a single stage:

```bash
./scripts/setup.sh deps      # install host dependencies (pacman)
./scripts/setup.sh fetch     # download + verify the virtio-win ISO; check Windows ISO present
./scripts/setup.sh extract   # extract VirtIO drivers from the ISO
./scripts/setup.sh secret    # prompt for the VM Administrator password, write secrets file
./scripts/setup.sh build     # packer init / validate / build the golden image
./scripts/setup.sh verify    # mount the built image read-only and check it's valid
./scripts/setup.sh all       # everything, in order (default)
```

During `secret`, you'll be prompted (silently) for the Windows Administrator
password to bake into the image. It's written to `packer/secrets.pkrvars.hcl`
with owner-only permissions and is **never committed** (see below).

> **Heads up:** the full run includes a Windows install and `sysprep`, which
> takes a while and reboots the build VM several times. It runs headless; to
> watch, connect a VNC viewer to the address Packer prints.

## What is *not* committed

The `.gitignore` deliberately excludes:

- **`packer/secrets.pkrvars.hcl`** — contains the Administrator password.
- **`packer/iso/`** — the ISOs (large; the Windows ISO is also not redistributable).
- **`packer/output-*/`** — the built image (large, and it contains the baked-in password).
- **`packer/vioscsi/`, `NetKVM/`, `Balloon/`** — driver extracts, regenerated by `extract`.

The password is injected at build time from the secrets file into the answer
files via Packer's `templatefile` — so the committed `.pkrtpl.hcl` templates
contain only a `${admin_password}` placeholder, never a real credential.

## Notes

- **Evaluation media:** the Windows ISO is a 180-day trial. When it expires,
  rebuild the golden image rather than trying to extend activation.
- **Scope:** this is an educational / home-lab setup. The target topology is a
  domain controller plus two SQL Server nodes forming a Windows Failover Cluster
  and an Always On availability group — built out in the Terraform and Ansible
  stages.
- **Platform:** the automation is Arch-specific (pacman). Porting the dependency
  step to another distro is the main change needed to run elsewhere.
